# FastAPI Clean Architecture

**Category:** backend · **Priority:** core · **Audience:** back-end

Structures a FastAPI service into domain/application/infrastructure/presentation layers so business logic stays transport-agnostic and testable. Use when starting a FastAPI service meant to last, adding a second entry point (queue consumer, scheduled job) beside HTTP, or refactoring a main.py-with-everything app into thin endpoints backed by use cases.
